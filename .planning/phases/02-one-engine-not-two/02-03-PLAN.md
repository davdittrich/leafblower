<objective>
Expansion wave 1: migrate the three remaining solvers that expose no R-only result fields —
`greg`, `greenkhorn`, `logit` — onto the shared dispatch table proven by plan 01.

Purpose: grow the shared table on the cheapest cases first, so the field-bearing solvers
(plans 04-06) migrate against an already-exercised pattern.
Output: three new case arms in `lbw::dispatch_solver`; three shrunk branches on each bridge.

**Migration recipe (identical for every solver in plans 03-06):**
1. Add the solver's arm to `lbw::dispatch_solver` in `src/calib_dispatch.hpp`: call the
   solver, copy `res.base.*` and its solver-specific fields into `DispatchResult`, set
   `alg_used`, move `best_weights`.
2. Replace the body of that solver's arm in `src/c_api.cpp` with a `dispatch_solver` call
   plus the narrowing copy into `rk_result_t` (superset-only fields are not copied).
3. Replace the body of that solver's method-string branch in `src/r_bridge.cpp` with a
   `dispatch_solver` call plus a copy into the existing `res_*` locals. SEXP packing
   (`r_bridge.cpp:1017-1127`) is not touched.
4. Re-verify both `Rf_error` swap-release blocks by reading them.
5. Update or delete the stale "mirrors r_bridge.cpp" line-number comment in `c_api.cpp`
   for that solver.
6. Run the targeted R test file + the Python parity case, then commit that solver alone.
</objective>
