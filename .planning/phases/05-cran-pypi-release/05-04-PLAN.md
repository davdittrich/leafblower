## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PyPI package registry → CI build environment | `cibuildwheel`, `twine`, `build`/`uv build`, `auditwheel` all execute arbitrary code pulled from PyPI at CI/local-build time |
| Third-party GitHub Action supply chain → CI execution | `pypa/cibuildwheel` runs arbitrary code inside the CI runner on every push/PR, across every matrix leg |
| CMake's FindLAPACK provider search → published wheel contents | A non-deterministic provider choice on macOS can vendor an unintended `.dylib` into a publicly distributed artifact |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-SC | Tampering | `cibuildwheel`, `twine`, `build` (all `[SUS]`-flagged by the automated package-legitimacy gate) | high | mitigate | Blocking `checkpoint:human-verify` above, never auto-approvable, confirming each package's PyPI project page and maintaining org before any version is pinned or locally installed |
| T-05-06 | Tampering | `pypa/cibuildwheel` GitHub Action (floating vs. pinned tag) | high | mitigate | Pin to the exact tag `v4.2.0` (confirmed via GitHub API at plan time), not a floating `@v3`/`@v4` major tag, per RESEARCH.md Pitfall 5 |
| T-05-07 | Tampering | macOS wheel vendoring an unintended non-system LAPACK `.dylib` (RESEARCH.md Pitfall 2) | medium | mitigate | `CMAKE_ARGS = "-DBLA_VENDOR=Apple"` explicitly pins the FindLAPACK provider to Accelerate, skipping the non-deterministic default search |
