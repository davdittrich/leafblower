## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| r-universe build infrastructure → published R binaries | r-universe clones this repo and builds artifacts that end users then `install.packages()` from; the artifact is produced by infrastructure we do not control |
| Public r-universe feed → end-user R session | `install.packages()` from a non-CRAN repo executes package install-time code from a third-party-hosted index |
| External registry repo (`davdittrich.r-universe.dev`) → build scope | Whatever `packages.json` lists gets cloned and built under this account's r-universe namespace |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-09 | Tampering | `packages.json` entry pointing at an attacker-controlled or wrong `url` | medium | mitigate | Task 2's acceptance criteria pin the exact URL `https://github.com/davdittrich/leafblower` and require catboostr/robscale entries stay byte-identical, so a mis-edit or collateral change fails the check rather than shipping |
| T-05-10 | Spoofing | Users installing from a `<owner>.r-universe.dev` domain that is not this account's | low | accept | The feed domain is derived from the GitHub account name and is stated verbatim in SC6 and in Task 3's verify command; no additional control is proportionate for a two-package hobby universe |
