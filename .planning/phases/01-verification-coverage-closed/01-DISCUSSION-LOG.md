## Property-test design

### Q1 — Which side owns the 50-dataset bound property test?

| Option | Description | Selected |
|--------|-------------|----------|
| R testthat only | KPI-02's wording came from the PRD's R-side acceptance criteria; six targeted bound tests already sit in `tests/testthat/`. No new dependency. Bounds enforced in shared C++ core, so one binding exercises the same path. | ✓ |
| Python pytest only | Parity harness already lives there; numpy makes generation and vectorized assertions terser. | |
| Both sides | Catches a binding-layer clamp bug the shared core would hide. Roughly doubles the work. | |

**User's choice:** R testthat only

### Q2 — How should the 50 datasets be generated?

| Option | Description | Selected |
|--------|-------------|----------|
| Fixed seed, 50 fixed datasets | Same 50 every run; fully reproducible, matches determinism constraint. Cost: a fixed probe, not a search. | ✓ (with constraint) |
| Random seed, printed on failure | Probes new territory each run; seed recorded for replay. Cost: non-deterministic CI. | |
| Fixed set + opt-in random sweep | Deterministic default, env-gated wider sweep. Cost: two code paths. | |

**User's choice:** Fixed seed — **with an added constraint:** "data must not be generated by
a normal distribution. Data needs to be skewed, fat-tailed."
**Notes:** This constraint drove Q3 and Q4. Rationale accepted: Gaussian inputs never push
calibrated weights against the clamps, so a bound assertion on normal data proves nothing.

### Q3 — What distribution generates the design weights (`d_i`)?

| Option | Description | Selected |
|--------|-------------|----------|
| Lognormal | Standard empirical shape for survey design weights; tail tunable via sigma. | |
| Pareto / power-law | Genuinely fat-tailed; stresses clamp and water-fill hardest. Risk: low tail index can make the problem infeasible rather than hard. | |
| Mixture: lognormal + heavy contaminant | Lognormal bulk plus small heavier-tailed fraction. Models mostly well-behaved weights with a few extreme influentials — the scenario the bounds exist to control. | ✓ |

**User's choice:** Mixture: lognormal + heavy contaminant

### Q4 — Should category marginals also be skewed?

| Option | Description | Selected |
|--------|-------------|----------|
| Skewed too — sparse cells | Dirichlet small-alpha or Zipf; sparse cells are the documented `RK_ERR_INFEAS` trigger. | |
| Keep marginals balanced | Isolates the tested variable per the repo's confound-gate discipline. | |
| Both, as separate dataset strata | Split the 50 into skew-only / sparse-only / both. Each violation attributable; interaction still probed. | ✓ |

**User's choice:** Both, as separate dataset strata

### Q5 — What happens when a generated dataset is infeasible or non-converged?

| Option | Description | Selected |
|--------|-------------|----------|
| Precheck, then assert bounds | Skip the assertion on `RK_ERR_INFEAS`/`NOCONV` but count skips and fail past a threshold. Mirrors the existing parity-protocol precheck. | |
| Assert bounds unconditionally | Bounds must hold on every returned vector regardless of status — FR-19/US-005 require the invariant at every inner iteration, and weights reflect the last iterate on NOCONV. Catches a clamp leaking only on the failure path. | ✓ |
| Tune the generator to stay feasible | All 50 feasible by construction; never probes the sparse-cell boundary the strata exist to reach. | |

**User's choice:** Assert bounds unconditionally
**Notes:** Raised because the sparse-cell strata from Q4 guarantee some datasets will be
infeasible — the same trap `test_solver_parity.py:7-11` added its convergence precheck for.

## Parity harness shape

**Finding surfaced mid-area (verified by direct collection runs):** the blocking DoD command
`cd python && ... pytest -q` collects 141 tests, all under `python/leafblower/`.
`tests/test_parity_weights.py` collects 8 tests — including the ONLY weight-vector parity
checks for `oris_soft` and `chebyshev` — and the gate never runs them. They pass, so nothing
is red; the assertions simply never execute. This reframed the area from cosmetic to
load-bearing: adding `oris_soft` to a matrix the gate does not collect is a no-op.

### Q1 — How should the two parity files be reconciled?

| Option | Description | Selected |
|--------|-------------|----------|
| Move tests/ into python/leafblower/ | One invocation collects everything; gate command unchanged. `wheel.exclude` already keeps such files out of the wheel. | ✓ |
| Widen the gate command | Keeps layout and the root-conftest sys.path trick intact; longer gate command. | |
| Unify into one parity module | Closes SC1 and SC2 in one structure; largest diff, rewrites passing tests. | |

**User's choice:** Move tests/ into python/leafblower/

### Q2 — Should the gate-collection gap be its own ticket?

| Option | Description | Selected |
|--------|-------------|----------|
| Yes — file it separately | Distinct defect class from the four CONCERNS.md coverage gaps: existing passing tests excluded from the blocking gate. Keeps the no-bundling rule. | ✓ |
| Fold into the phase plan | Roadmap already says to file parity-gap tickets at plan time. | |

**User's choice:** Yes — filed as `leafblower-x7n8` (P0) during this discussion, validated.

## testthat 3e scope

**Scouting result presented before the questions:** across 94 test files, `context()` appears
in 13 and `expect_that` / `expect_is` / `expect_equivalent` in zero. Residual risk is
`expect_equal` under waldo, which cannot be grepped for.

### Q1 — Adopt edition 3, or correct the docs to match edition 2?

| Option | Description | Selected |
|--------|-------------|----------|
| Adopt 3e | Makes CLAUDE.md's claim true; waldo strict comparison suits a package whose philosophy is absolute statistical correctness. Fallout bounded. | ✓ |
| Stay on 2e, fix the docs | Zero risk to 94 files; keeps laxer `all.equal` semantics permanently. | |

**User's choice:** Adopt 3e

### Q2 — How should a newly-failing waldo assertion be treated?

| Option | Description | Selected |
|--------|-------------|----------|
| Every new failure is a finding | A test that only passed under `all.equal` tolerance was hiding something. Matches the roadmap note and the anti-pivot rule. | ✓ |
| Triage: relax pure-format failures | Faster, but the triage judgment is where a real bug gets mislabeled as an artifact. | |

**User's choice:** Every new failure is a finding

### Q3 — How should the migration land as commits?

| Option | Description | Selected |
|--------|-------------|----------|
| One commit, whole suite | Never half-migrated; large diff across up to 94 files. | |
| Split: enable, then fix | Reviewable in isolation; violates "complete = gates green" at intermediate commits. | |
| Fix first, then enable | Migrate deprecated constructs while green on 2e, flip the edition last. Every commit green; the flip isolates true waldo fallout. | ✓ |

**User's choice:** Fix first, then enable
