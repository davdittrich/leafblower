<objective>
G-03-1 (UAT gap), continued: `greenkhorn` and `sinkhorn` are the two leafblower methods whose
doc-named closest competitor lives outside R entirely. `docs/methods/greenkhorn.md`'s own
"Practitioner implementations & use cases" section names Python Optimal Transport (POT,
`[flamary2021pot]`) as "the primary open-source vehicle" for Greenkhorn, available as
`ot.bregman.greenkhorn` -- the exact wording the UAT gap itself anticipated ("greenkhorn's
closest competitor is likely POT's ot.bregman.greenkhorn"). `docs/methods/sinkhorn.md` names
the same library for Sinkhorn.

Both method docs' own "How leafblower deviates" sections state a real structural mismatch: POT
solves the classical TWO-marginal transport problem (a transport matrix P in R^{n x n}, cost
matrix M, regularization reg); leafblower's greenkhorn/sinkhorn solve the K-MARGIN (K >= 1)
box-bounded survey-calibration problem generalizing that via a cyclic Gauss-Seidel sweep. Per
`docs/methods/oris.md`'s own "Relation to Sinkhorn and Greenkhorn" section: "In the pure
2-marginal case Sinkhorn and cyclic IPF coincide." This plan therefore builds the ONE
mathematically faithful comparison available -- a dedicated K=2-margin fixture, run through
both engines -- rather than force an apples-to-oranges K>2 comparison POT's API cannot express,
per the gap's own instruction to document (not force) a mismatched comparison.

`POT`'s `greenkhorn`/`sinkhorn` functions take only `(a, b, M, reg, ...)` -- a cost matrix plus
scalar regularization, no bounds argument (confirmed via PyPI/POT docs fetch this session,
recorded in `03-RESEARCH.md`'s extended Package Legitimacy Audit, OK verdict, no new checkpoint
needed). Setting `M = -log(prior)`, `reg = 1` recovers `exp(-M/reg) = prior` exactly, making
POT's kernel equal to leafblower's own `X_init` prior -- the SAME `min_X KL(X||X_init)` s.t.
margins problem, for K=2. Both arms must therefore run effectively unbounded (POT cannot
enforce a box), a caveat stated explicitly, not glossed over.

Purpose: close the two Python-reachable methods in G-03-1's per-method coverage gap.
Output: new `benchmarks/greenkhorn_sinkhorn_vs_pot.py`, its result CSV, and
`benchmarks/run_honest_gate.sh` extended to run it (D-12's one-command reproduction).
</objective>
