Fixture, `medium_100k_5margins`: `set.seed(304)`, `n <- 100000L`, `K <- 5L`, `nj <- 4L`.
Build a data frame of `K` factor columns named `m1`..`m5`, each sampled from `nj` levels,
using `newton_kl_bench.R`'s `as.data.frame(lapply(seq_len(K), ...))` construction. Give each
margin a skewed target vector (a fixed non-uniform probability vector normalised to sum 1,
e.g. proportions in the neighbourhood of 0.45/0.30/0.15/0.10) so the calibration is a real
adjustment and not a no-op. This shape is chosen deliberately to match the shape the PRD's
own contradictory medium-scale target names (100K rows, 5 margins, 3-5 categories each), so
the number this produces directly retires that contradiction rather than sitting beside it
(SC2). Because `nj^K` is 1024 and `n` is 100000, `M_cell/n` is far below 1 — this is a
non-degenerate, compression-benefiting class, deliberately NOT the K=20 uniform-random class
that RESEARCH.md Pitfall 3 warns is the wrong fixture for a positive claim.

`max_weight <- 3` and `bounds_mode = "unit"` for the leafblower arm. The `bounds_mode`
choice is load-bearing and must be commented as such: the default `"cell"` enforces bounds
only in cell aggregate, whereas `survey`/`icarus`/`ReGenesees` all enforce a per-observation
bound on the ratio `g = w/d`. Comparing a cell-aggregate leafblower arm against
per-observation competitors would be comparing two different optimisation problems and would
make the timing meaningless. With unit design weights, `bounds_mode = "unit"` and
`max_weight = 3` corresponds to the competitors' `bounds = c(0, 3)` on `g`.

Shared, arm-independent metric helpers — define ONCE and apply identically to every arm's
returned weight vector, never accepting a package's self-reported convergence number:
  - `margin_max_error(w, df, tgt)` returning `max_k max_j |sum(w * (df[[k]] == j)) / sum(w) - tgt[[k]][j]|`.
  - bound compliance as `max(w)` and `min(w)` on the weight vector normalised so `sum(w) == n` (leafblower's exit convention per `lbw::finalize_weights`; normalise the competitors' weights the same way before comparing so `max_w` is on one scale).
  - `deff` via `leafblower::design_effect(w)` and `n_eff` as `n / deff`.
Compute the KL/margin sums cancellation-free per the project's numeric philosophy — do not
form the error as a difference of two large accumulated totals when the per-category
proportion can be accumulated directly.

Arms for this task (exactly two — the remaining competitors arrive in plan 02):

Derive `population` from the same `tgt` list scaled to `n` so both arms are given identical control totals; read the actual argument contract from the installed help before writing the call rather than assuming it.

Confound control (this is the point of the phase, not a nicety): the two arms must differ
ONLY in the implementation under test. Same fixture object, same control totals, same
per-observation bound, same convergence tolerance target, same process, same single-thread
BLAS envelope. Give each package a comparable convergence tolerance rather than each
package's own default, and record what was requested in the `note` column, so a speed number
can never be won by stopping earlier than the other arm.

per-arm-loop form is correct; CLAUDE.md's interleaved-in-one-`bench::mark()`-call rule

distinction in a comment so a later reader does not "fix" it into an interleave.
