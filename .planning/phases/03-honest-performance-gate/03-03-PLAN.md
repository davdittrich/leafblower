  <context>
    D-06 leaves the metric to Claude's discretion, to be picked once the fresh benchmark
    actually ran — it has now run, and the full table from 03-02 is on disk at
    `benchmarks/results/oris_soft_vs_competitors.csv` with its machine provenance at
    `benchmarks/results/oris_soft_vs_competitors_env.txt`.

    D-10 makes the restated number a hard pass/fail gate rather than a reported measurement.
    That combination is a one-way door: a threshold published in the README and asserted in
    a testthat gate cannot be quietly relaxed later without walking back a public claim.
    D-06's discretion grant covers which number is the strongest honest differentiator; it
    does not cover unilaterally setting the number a maintainer will be held to.

    The developer framed the actual innovation as: high speed, bounded weights, small design
    effect, therefore more effective observations. That phrasing is on the record in
    CONTEXT.md § Specific Ideas and should inform which of the measured columns carries the
    claim.

    Present, before asking: the full measured table (all three input classes, all arms, all
    17 columns) rendered readably; the machine line; each competitor's requested convergence
    tolerance; and, for each candidate metric, the headroom between the measured value and a
    proposed ceiling.
  </context>
