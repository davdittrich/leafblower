# Performance

Every number on this page is transcribed from one measured artefact —
`benchmarks/results/oris_soft_vs_competitors.csv` and its companion
`benchmarks/results/oris_soft_vs_competitors_env.txt` — regenerated by one
command (see *Reproduction* below). No figure here is estimated, aggregated
from a different run, or carried forward from an earlier document.

## Headline claim

On the `medium_100k_5margins` input class (100,000 observations, 5 margins,
4 categories each), `oris_soft` calibrates in **0.0427s** wall time, achieving
**max margin error 3.35e-05**, honouring the `[0, 3]` per-observation weight
bound (`max_w = 3.0000`, `min_w = 0.1299`), and retaining **n_eff = 67,489.4**
effective observations out of 100,000 raw rows.

This is a **paired** claim, deliberately: the speed figure is never published
without the accuracy, bound-compliance and effective-observations figures
that were achieved alongside it — all four computed by the same benchmark
script from the arm's own returned weight vector, never from a package's
self-reported convergence status. `tests/testthat/test-bench-gate.R`'s
`honest gate:` block regresses against all four together
(`LBW_BENCH_GATE=1`): `wall_s <= 0.5`, `max_error <= 1e-3`, the `[0,3]` bound,
and `n_eff >= 60000`. A speed claim detached from what it cost in accuracy is
the exact failure this page and its gate exist to end.

### `k2_margin_pot_equiv` — greenkhorn/sinkhorn vs POT (K=2-margin special case)

This comparison class exists **only** because leafblower's K-margin cyclic
sweep coincides with POT's 2-marginal entropic-OT formulation at K=2 — see
[`docs/methods/oris.md`](methods/oris.md)'s "Relation to Sinkhorn and
Greenkhorn" §Axis 1: "In the pure 2-marginal case Sinkhorn and cyclic IPF
coincide; with `K > 2` margins they differ in sweep structure." Both arms ran
effectively unbounded (`max_weight` set beyond what the fixture can reach)
because **POT has no box-constraint mechanism at all** — this class is **not
representative** of leafblower's normal `K > 2`, bounded workload. Measured
on a `n=10,000`, 2-margin, 4-category fixture (`benchmarks/greenkhorn_sinkhorn_vs_pot.py`),
transcribed verbatim from `benchmarks/results/greenkhorn_sinkhorn_vs_pot.csv`.

| arm | wall_s | max_error | max_w | min_w | n_eff |
|---|---|---|---|---|---|
| `leafblower_greenkhorn` | 0.002191 | 5.160e-09 | 2.4241 | 0.1669 | 7110.6 |
| `leafblower_sinkhorn` | 0.002006 | 1.665e-16 | 2.4241 | 0.1669 | 7110.6 |
| `pot_greenkhorn` (`ot.bregman.greenkhorn`) | 0.000279 | 6.328e-15 | 2.4241 | 0.1669 | 7110.6 |
| `pot_sinkhorn` (`ot.sinkhorn`) | 0.000109 | 5.551e-17 | 2.4241 | 0.1669 | 7110.6 |

All four arms converge to the identical `max_w=2.4241...`/`n_eff=7110.59...`
solution, confirming the equivalence empirically, not just theoretically.
POT has no per-observation identity — only a solved cell-mass table — so its
`max_w`/`min_w`/`n_eff` are derived from an implied per-observation weight
`T[i,j]/K_prior[i,j]` within each cell (cell-uniform exchangeability under
this margin-only objective).

## Methodology

Held constant across every arm on a given input class: one fixture object,
one set of control totals, one per-observation bound convention, one
requested convergence tolerance (each package's own canonical default — see
the *Results* tables above), one process, and the single-thread BLAS
envelope recorded above (`OMP_NUM_THREADS=OPENBLAS_NUM_THREADS=MKL_NUM_THREADS=1`).

Every arm's accuracy (`max_error`), bound compliance (`max_w`, `min_w`) and
design effect (`deff`, `n_eff`) are computed by the benchmark script's own
helpers, applied identically to that arm's returned weight vector — never
read from a package's self-reported convergence status. A package that
reports "converged" is not taken at its word; its returned weights are
re-graded independently.

**Why `bounds_mode = "unit"`.** `leafblower`'s default `bounds_mode = "cell"`
enforces bounds on the aggregated cell mass, not on each observation's own
weight ratio. `survey::calibrate`, `icarus::calibration` and
`ReGenesees::e.calibrate` all enforce a hard per-observation bound on the
weight ratio (`bounds=`/equivalent). Comparing `leafblower`'s default mode
against that convention would be comparing solutions to two different
problems, so every `leafblower_oris_soft`/`leafblower_raking_accelerated`
figure on this page uses `bounds_mode = "unit"` to match.

## Reproduction

One command regenerates every figure on this page:

```
bash benchmarks/run_honest_gate.sh
```

It runs under the single-thread BLAS envelope recorded above and writes
`benchmarks/results/oris_soft_vs_competitors.csv` and its `_env.txt`
companion fresh. The opt-in regression gate reads that CSV back:

```
LBW_BENCH_GATE=1 CI=1 NOT_CRAN=true Rscript -e "testthat::test_dir('tests/testthat', filter='bench-gate', stop_on_failure=TRUE)"
```

`tests/testthat/test-bench-gate.R`'s `honest gate:` block asserts, on
`leafblower_oris_soft`/`medium_100k_5margins`: the `[0,3]` bound, `max_error
<= 1e-3`, `wall_s <= 0.5`, and `n_eff >= 60000`. The gate stays opt-in — it
does not run under the default `devtools::test()` invocation used for the
project's Definition of Done, per the project's split between
correctness-gating (always on) and performance-gating (explicit opt-in).

## Known limit

The `known_limit_k20_uniform` class (K=20 uniform-random margins, 5
categories each, `max_weight = 3`) demonstrates why the retired composite
"under 30 seconds AND under 1e-6" target is not achievable on this package
with any solver currently implemented. The reason is measured, not asserted:
`m_cell / n = 1.0000` — every one of the 500,000 observations lands in its
own unique 20-dimensional cell, so the cell compression that ORIS's
per-iteration advantage depends on yields nothing at this shape.


Measured on this class: `leafblower_oris_soft` reaches `max_error = 5.229e-03`
in 7.39s under a bounded 500-iteration budget; `leafblower_raking_accelerated`
(`accelerate = TRUE` — the acceleration scheme is described only by this
argument, not named, since this phase did not verify which scheme it
selects) reaches `max_error = 1.516e-03` in 3.39s. Neither clears the retired
`1e-6` target. Raking-with-acceleration is this package's documented
fallback path for zero-compression-benefit inputs.

This finding is not new: `docs/investigations/2026-04-23-kk1204-convergence.md`
(commit `3effd3a`) first measured `m_cell / n = 1.0000` on the same input
shape and found the composite gate structurally unreachable. The follow-up
research spike, `docs/investigations/2026-05-02-ylsy-cp-ipm-spike-result.md`,
tried two additional solver families (Chambolle-Pock primal-dual and an
interior-point Newton method) specifically to see whether a different
algorithm could break the ceiling; neither did, and the ticket tracking that
research (`leafblower-ylsy`) closed with the conclusion, quoted verbatim from
its close reason:

> kk1204 is a near-infeasible degenerate fixture (DEFF 8000-14000, n_eff
> 71-118 across ALL solvers — ieppa, newton_kl, auto), not an algorithm gap.

That closure was measured on a more severely skewed variant of the K=20
fixture than the milder-skew `known_limit_k20_uniform` class measured for
this page (see the two solvers' figures above) — the two are related but not
numerically interchangeable, and this page does not restate the closure's
own numbers as if they were re-derived here. Both documents agree on the
same qualitative conclusion this page's own measurement supports: at
`m_cell / n = 1.0000`, the difficulty is a property of the input shape, not
a gap in any solver tried.

## Competitors

The `oris`/`oris_soft` comparison in the headline table above is scoped to
`survey::calibrate`, `icarus::calibration` and `ReGenesees::e.calibrate` —
the full multi-package survey-calibration study is separate work, not this
page. These three were selected because they are the R ecosystem's
bound-supporting IPF/raking implementations (`ipfp`, `mipfp` and `ipfn`
support no explicit bounds); see the practitioner implementations table and
the "Bounds handling" row of "How leafblower deviates" in
[`docs/methods/oris.md`](methods/oris.md) for the full grounding and
citations. This page does not restate that bibliography — `oris.md` and
`docs/methods/references.bib` are the canonical citation source.

measured on `medium_100k_5margins` (row cited above, in the "per-method
competitor coverage" table) except `sinkhorn`/`greenkhorn`, which are
Python-reachable-only and measured on the `k2_margin_pot_equiv` class instead
(row cited above):

**Why the competitors were not run at the large scale.** `survey`, `icarus`
and `ReGenesees` each build a dense observation-by-category model matrix
internally. At `large_stepstone_fulldata`'s measured shape
(1,582,732 observations x 836 categories), that matrix projects to
`1,582,732 x 836 x 8 bytes ≈ 9.9 GB` — computed from the fixture's own
measured dimensions, not asserted. This is itself a comparative finding: it
is a scaling boundary these implementations hit that `leafblower` (whose
cell-compression design keeps the working set at `M_cell`, not `n x
categories`) does not.
