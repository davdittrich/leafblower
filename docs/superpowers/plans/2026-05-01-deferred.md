## leafblower-gvza — research(chebyshev): ν dual correction without inducing INFEAS

**Status:** research spike, not implementation.

**Why no plan yet:** Reference elimination gives `schur_nu = 4.19 > 0`
(non-degenerate), but applying `dnu = (-r_nu - eᵀ·dlambda) / schur_nu` causes
`RK_ERR_INFEAS` because the LP slack structure already maintains `W ≈ n_d`
implicitly. The math fix is unknown — possibilities include a modified LP
formulation explicitly including `W = n_d`, alternating-direction updates, or
Lagrangian relaxation. None of these are validated yet.

**Unblock:** dedicated math write-up. Open a `docs/investigations/` note,
derive the corrected dual update analytically, and run a small numeric
sanity-check (1-margin synthetic problem) before producing an implementation
plan.

## leafblower-rx1 — research: `log_prod_all` Gauss–Seidel vs Jacobi convergence study

**Status:** deferred research; awaits benchmark-driven decision.

**Why no plan yet:** The proposed precompute (`log_prod_all[c] = Σ_m
lf[m][g_m(c)]` at the top of each outer iter) trades ~2× per-iter speed-up for
a sweep-semantics change from Gauss–Seidel to Jacobi. The decision criterion
(per the ticket) is *iter-count inflation < 2× ⇒ apply; else reject*. The data
to make that call does not exist.

**Unblock:** run a `(n, K, bound-tightness)` grid bench to measure per-iter
vs total-time speed-up for both variants. Bench should reuse the
`benchmarks/blse_routing_sweep.R` harness once that lands (leafblower-2jw).
After the bench, file an implementation ticket if iter-count inflation is
under 2×.

## leafblower-ylsy — kk1204 convergence research: algorithmic replacement for slow-rate regime

**Status:** open research; multiple accelerator paths already rejected.

**Why no plan yet:** Empirical 2026-04-24 finding shows kk1204 (n=1M, K=20,
max_weight=3) exhibits pure slow-rate Sinkhorn convergence (errRp ≈ iter^{-0.5}
asymptotic). APVA, Joint Anderson, and Halpern mixing have all been tested and
rejected for this regime. raking+SQUAREM with the obs-level CBB-norm geometry
fix solves stepstone-fulldata but kk1204 differs structurally (K=20 dense,
M_cell/n = 1.0 → zero iEPPA compression), and ieppa is 22× slower than raking
per-iter on this shape.

**Unblock:** the next algorithmic candidates listed in the ticket (Newton on
constraint duals, Chambolle–Pock primal–dual, mirror descent with entropic
regularization) need a literature scan and a single-method pick before any
implementation plan can be written. The acceptance criterion is explicitly
*decide P2.1 ship-as-is OR commit to one replacement pathway* — not yet ready
for code.
